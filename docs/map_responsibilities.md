# 地図の責務と状態の所有

`Map.svelte`は地図の初期化・破棄、カメラ操作、表示更新の調整を担当します。
機能の状態を一つの巨大なコントローラーへ移す構成にはせず、以下の単位で所有します。

| 所有先                                            | 責務                                                                             |
| ------------------------------------------------- | -------------------------------------------------------------------------------- |
| `src/lib/states/navigation.svelte.ts`             | ページが生成する選択・役割別ハイライト・経路の共有状態。Leaflet・DOMに依存しない |
| `src/lib/map/state/view.svelte.ts`                | 表示中の建物、建物ごとの階、建物の色と選択の維持                                 |
| `src/lib/map/state/floors.ts`                     | 公開階への補正と接続先への階の同期。入力を変更しない純粋関数                     |
| `src/lib/map/svgLayers.ts`                        | SVGの取得・検索、基本図・全体図・階別図の表示、画面上の建物形状への変換          |
| `src/lib/map/poiLayer.ts`                         | POIの操作イベント、強調表示、吹き出し、イベントと表示資源の破棄                  |
| `src/lib/map/markerLayer.ts`                      | SVG図形を使わない施設アイコン、選択・役割別の強調、階別表示、表示資源の破棄      |
| `src/lib/map/routeLayer.ts`                       | 経路線、始終点・階移動マーカー、ラベル配置、表示資源の破棄                       |
| `src/lib/components/BuildingFloorControls.svelte` | 階操作パネルと接続線、サイズ変更と階変更の通知                                   |

## 状態の置き場所

アプリ内の複数機能で共有する状態は`lib/states/`、地図機能内だけで使う状態は`lib/map/state/`に置きます。
`states/`は所有範囲を示す配置であり、グローバルな可変インスタンスを置く場所ではありません。
`createNavigationState()`を親で呼び、同じモデルを利用側へ渡します。

POI選択の正本は`navigation.highlights.selected`です。`selectedPoi`はそこから導出します。
経路にはnode ID、ハイライトにはPOI IDを使用し、それぞれ独立して更新できます。
カメラ移動は別の操作です。共有状態を変更しただけではPOIへ飛行しません。

`Map.svelte`の`navigation`は必須です。親がモデルを生成し、選択・ハイライト・経路の変更はモデルのメソッドへ統一します。
地図の公開メソッドはカメラ操作の`focusOnPoiId()`のみです。モデルの自動生成や選択を同期する互換処理はありません。
APIの利用例と受理・表示の違いは`poi_highlight.md`を参照してください。

## 更新と破棄

地図イベントと共有状態の変化を`Map.svelte`が受け、階別図・POI・経路の可視性を更新します。
操作パネルを計測・配置した後に経路ラベルを配置し、互いを障害物として扱います。
POIや経路の描画モジュール同士は直接呼び出しません。

破棄時は更新予約を取り消し、地図イベントを解除してから各モジュールの`dispose()`を呼びます。
SVG取得は中断し、完了が遅れても破棄済みDOMを更新しません。
親が所有する選択・経路は、地図の破棄に伴って変更しません。

## テスト

テストは対象コードが属するディレクトリの`tests/`に配置します。
階のルールと共有状態の操作はNode環境、描画と機能間の連携はChromiumで検証します。
Vitestの既存の検索パターンは`tests/`配下も対象にするため、設定変更は不要です。
